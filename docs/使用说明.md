# APIFaultLab 使用说明

APIFaultLab 的工具栏弹窗用于查看当前页状态、开关采集和停止模拟。打开 F12 开发者工具，选择 **APIFaultLab** 标签页，即可配置 GET 或 POST 模拟、批量规则、导入接口文档和保存测试方案。

## 构建和加载

使用 Node.js 22.12 或更新的受支持版本。在项目目录运行 `npm ci`、`npm run typecheck`、`npm test` 和 `npm run build`。构建产物为 `.output/chrome-mv3`。

在 Chrome 128 或更高版本打开扩展程序管理页面，启用开发者模式，选择「加载已解压的扩展程序」，并选择上述输出目录。已有旧版本时，在扩展管理页重新加载扩展。打开要测试的页面，按 F12 选择 **APIFaultLab**，标签过多时可从 `»` 中找到。更新扩展时已经打开的 DevTools，可以关闭后重新打开以注册标签页。

从 DevTools 直接打开时，按需点击「授权此站点」。点击 Chrome 工具栏里的扩展图标也会为当前打开的网站提供临时页面访问权限。

## 首次验证

1. 在同一标签页打开 DevTools，选择 **APIFaultLab**，执行一次查询，确认工作台出现对应的 POST。
2. 点击接口行，添加模拟规则并选择空列表。响应和匹配范围显示在详情顶部，点「启用规则」即可应用。再次查询，检查页面空态和本轮命中。合成结果在工作台显示，真实网络请求可在 DevTools Network 查看。
3. 在同一标签页刷新页面。等待「等待页面确认规则」结束，再次查询应命中原规则。换到另一个标签页时应保持独立。如果面板提示会话未能保存，本页启用的规则可能需要在刷新后重新设置。
4. 在请求列表中选择「停止本页规则」可仅停止当前页面的规则。工具栏的「停止标签页规则」覆盖该标签页内所有页面，单条规则可以在接口详情里停用。等停止确认后再执行查询。工作台应记录真实响应，页面应恢复原有列表。如果应用从缓存读数据，可切换查询条件或从页面重新加载数据。
5. 通过「导入」加载本地 OpenAPI 3.0/3.1、Swagger 2.0 或 APIFaultLab 目录，核对将加入的接口。保存一个方案再重启浏览器，确认可预览合成响应和触发说明。

## 导入和管理接口目录

「导入」支持本地 OpenAPI 或 Swagger 的 JSON/YAML，以及 APIFaultLab 接口目录 JSON。单个文件限 8 MiB，每次最多导入 500 个操作。解析成功后默认选中全部操作，可以按需调整，然后从预览顶部加入当前页面。默认只保存接口信息。需要使用文档中的响应示例时，可以勾选「同时导入响应示例」，并先检查示例中的业务数据。

选中操作后会预览新增、更新和移除数量。默认合并当前页面的目录，保留未被覆盖的已有操作和示例。可手动选中替换整个当前页面目录，或在「已导入目录」中移除指定接口。这些操作只管理导入记录，已观察的请求、模拟规则和已保存方案各自保留。

从代码、文档或已获授权的请求记录整理接口时，可使用随仓库提供的 [APIFaultLab 目录 Skill](../skills/apifaultlab-catalog/SKILL.md)。目录必须和当前网页 URL 一致。共用一个 POST 的多个操作在接口详情分开显示，点击「创建规则草稿」可带入单个操作的匹配条件。核对条件与响应后再启用。[目录格式与字段说明](../skills/apifaultlab-catalog/references/接口目录格式.md)

## 备份和恢复数据

在 F12 面板打开「方案」里的「数据备份」，点击「导出 JSON」。文件包含这个 Chrome 配置文件中 APIFaultLab 的全部已保存方案、已导入的接口目录、站点忽略规则和自定义场景。已保存的响应正文和 URL 可能含有业务信息，分享前请检查。

恢复时选中 JSON 文件，核对各类配置的新增、已有和冲突数量，再确认恢复。重复配置会跳过，冲突时保留本机配置。恢复后可到对应页面手动启用方案。已启用的会话规则、临时请求记录和网络采样不随备份恢复。

卸载扩展前先导出文件。更换电脑、Chrome 配置文件或扩展 ID 后，可以从文件恢复。如果面板提示本地数据读取失败，在「数据备份」里重试读取。读取恢复前，扩展会暂停保存，保护原配置。

如果提示「本地配置格式无法识别」，先在「数据备份」下载原始 JSON，另行保管。用「导出可读取配置」生成备份可保留仍然有效的条目，并显示跳过数量。可在干净的 Chrome 用户配置里恢复这份备份，原始配置留在当前用户配置中。

## 方案草稿和分享

- 在「方案」里新建草稿，填写名称并添加至少一个接口。添加后会展开这条规则，可以选择异常响应并按需设置请求匹配条件。有运行规则时，也可以从当前规则创建。测试前准备、操作步骤和预期页面表现放在「复测备注（选填）」中，保存后可在方案预览查看。保存方案后，可从预览手动启用模拟。
- 选中保存的方案后，预览顶部会显示规则数量和替换范围。点击「启用方案」即可替换当前页面的规则，继续滚动也能看到这个按钮。
- 「返回并保留」、按 Esc 或切换页面都会保留草稿。回到原页面，打开面板中的「继续方案草稿」恢复编辑。草稿在当前 DevTools 面板内保留。要跨会话使用，请保存方案。
- 从方案预览打开「分享方案」。默认只导出不含页面地址、正文和匹配值的摘要。对方需要导入时，在核对方案内容后选「包含可导入的完整方案」。通过「数据备份」导入后会新增保存方案，由用户手动启用。

## 过滤和忽略接口

- 搜索框可按方法、路径或名称查找。「业务」「静态」「地图」可快速缩小列表，地图分类会识别常见瓦片路径、矢量瓦片和样式文件。
- 筛选栏右侧的「忽略参数」按当前站点保存。开启后忽略页面 URL 和 Hash 路由中的查询参数（例如翻页 `?page=2`），在分页或切换筛选条件时保留同一页面组的接口列表和模拟规则。
- 勾选可见接口后点击「忽略所选」。通过「忽略规则」可以一次填写多个路径前缀，每行一个，例如 `/assets/`、`/styles/`、`/map-tiles/`。添加前会显示当前匹配数。填写完整接口地址可以只匹配该 API 来源，例如 `https://tiles.example.test/tiles/`。
- 忽略设置按当前页面的站点保存，跨该站点的页面和浏览器重启复用。在「已忽略」或「忽略规则」里恢复。忽略作用于请求目录和普通视图，已有模拟规则可以从「有规则」查看和停用。
- 全选、忽略和批量模拟按当前可见结果操作。切换筛选后，选中但已隐藏的接口会单独计数。
- 请求记录达到上限时，工作台优先保留有规则的请求和业务接口。无请求记录的已配置规则仍可从「有规则」找到。
- 批量修改会逐条保留匹配条件，只更新响应。具体路径仅被模板规则覆盖时会跳过。要批量修改整个模板，请选中模板行。详情顶部显示新增、更新数量，并提示覆盖整个接口或路径模板的规则。选择响应后，直接点击顶部的启用按钮。

## 快捷异常场景

单接口编辑和批量设置共用场景选择器。可按类别选择 HTTP 400、401、403、404、429、500、502、503、504，以及空列表、空对象、`null`、204、慢响应和网络错误。429 场景自带可编辑的 `Retry-After` 秒数。请求条件支持查询参数、请求头和 JSON 字段；响应编辑器支持添加自定义响应头（如 `X-Total-Count`、`X-Trace-Id`）以及设置「最多生效次数」（例如设为 2 次，前两次返回 503，第 3 次自动放行真实请求，用于验证前端重试与恢复逻辑）。

从请求列表顶部的「自定义场景」可新建、编辑或删除模板。填写名称，设置 HTTP 状态码或勾选模拟网络错误。响应设置和预览默认展开，可直接修改正文和延迟并查看结果。也可在规则编辑器将当前响应保存为场景。保存时检查正文是否含有真实数据。场景可以跨页面复用，在规则编辑器的「更多场景」中选用，确认草稿后再启用。

## 页面接入边界

支持主页面的 Fetch 和异步 XHR。为站点授权并准备首屏接入后，同标签页、同源刷新时，首屏脚本会让这些请求等后台确认原会话的规则。确认后按规则模拟或放行。会话无法确认时，请求会在页面报错。重新启用规则或点击「停止标签页规则」确认后，再触发原操作。仅有临时页面访问权限时，当前文档的模拟仍可用，首屏保护需要站点授权。

首屏保护需要网页允许会话存储，页面只保存一个会话标记。Worker、iframe、同步 XHR、`sendBeacon` 和原生表单不在拦截范围内。

弹窗和工作台共享同一标签页状态。关闭界面后采集和模拟按当前开关继续。工具栏弹窗中可暂停采集或停止模拟。跨站导航、关闭标签页或者重启浏览器结束运行会话，本地已保存方案仍可再次加载。

F12 面板与后台断开时，会保留已显示的接口和勾选状态，并在面板可见时自动重连。可以继续勾选接口和编辑草稿，页面确认接入后再启用模拟。点击工作台顶部的状态可主动检查页面接入。如果后台已连上但页面仍未就绪，点击「重试接入」。如果刚更新扩展，关掉并重新打开 DevTools，以加载新版面板。

规则编辑器可采集来自网页的真实响应。在 20 秒内触发相应请求，编辑器会显示采集成功、读取失败或超时。接口的所有操作正在模拟时，需要先停用覆盖它的规则。

## 本地验收页

在项目目录运行 `node examples/manual-demo/server.mjs`，然后手动打开 `http://127.0.0.1:4173/orders` 和 F12 面板。示例服务只监听本机，重启服务会清空计数。

1. 点击「查询订单」和「查询客户」，确认同一个 `POST /api/query` 能采集两种操作。在接口详情添加规则，使用 JSON 条件 `/operationName` 等于 `ListOrders`，响应选 HTTP 429。
2. 记录「服务器收到的 POST」计数，再分别查询订单和客户。订单应显示 429，服务端订单计数不增长。客户应返回 200，服务端客户计数增长一次。接口详情仍应显示订单规则的命中结果。
3. 在同一接口添加 `ListCustomers` 的条件规则，再勾选这行批量改为 404。预览应显示两个独立的条件。应用后点击「查询版本」，这个未匹配的 XHR 操作应继续返回真实的 200，版本计数增长一次。
4. 点击「发出 125 个瓦片请求」，检查业务接口和模拟规则仍在。准备首屏接入后，可分别为 `StartupProbe` 和 `StartupProbeXhr` 配置异常响应。同页刷新后，页面启动区应显示这两个模拟响应，服务器收到的对应 POST 计数应保持不变。
5. 点击「停止标签页规则」，再触发查询。确认收到 200，且服务端计数增长一次。需要模拟 Chrome 后台复位时，停止后从扩展管理页关闭后台 Worker，再同源刷新，确认规则未恢复。

自动回归使用 `npm run typecheck`、`npm test` 和 `npm run build`。需要验证真实 Chrome 行为时，在构建后显式运行 `npm run test:chrome`。脚本通过 Chrome 自带的 DevTools 打开工作台，使用临时浏览器配置、扩展构建的临时副本和随机端口的本地验收服务，仅对临时副本预授本地站点访问权限。可用 `APIFAULTLAB_CHROME_PATH` 指定 Chrome 路径。
