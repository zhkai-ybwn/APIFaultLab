# 接口异常测试插件需求设计

**APIFaultLab · 需求评审稿 v0.4 · 2026-11-23**\
配套文档 [界面与交互设计](界面与交互设计.md) · [技术选型与架构设计](技术选型与架构设计.md)

## 1. 产品目标

面向在开发和测试环境验证网页异常表现的前端开发及测试人员。工具栏弹窗提供状态、采集开关和停止操作。F12 的 APIFaultLab 标签页自动显示被检查页面 URL 下的接口。开发者可以从当前列表对 GET、POST 等请求设置异常，勾选多条批量启用，也可以先导入接口文档再配置。

首版验证从真实数据开始，模拟后重新触发看到异常或空态，停止后重新触发回到真实数据。常用组合保存为方案，跨刷新或重启后可加载。

## 2. 核心使用流程

1. 在业务页面按 F12，选择 APIFaultLab 标签页。工作台显示当前页面 URL 对应的接口组和本次会话已知的接口。页面发生后续请求时补充列表。也可用「导入文档」提前添加接口。工具栏弹窗可随时核对采集开关。
2. 在 `POST /api/orders/search` 行选择空列表。若多个业务操作共用 `POST /api/query`，可在同一接口行按 JSON 字段配置，如仅 `operationName = ListOrders`。也可以勾选后点击「批量设置」。
3. 等待工作台显示「模拟中」，在原页面查询、切换菜单或操作表单。工作台显示这一轮规则是否接到请求以及实际返回结果。同标签、同源刷新后等待规则自动恢复。
4. 停止模拟后，依据提示重新触发业务操作。核对工作台记录了真实请求，并检查页面是否恢复。把常用规则、触发步骤和预期结果保存为方案。

## 3. 页面 URL、接口发现与文档导入

| 需求 | 首版行为 |
| --- | --- |
| 当前页归组 | 默认按主页面实际 URL 归组。页面 URL 不变时，页内标签、弹窗和局部状态沿用同一组。URL 变化时加载新组。同组内可按操作条件区分共用接口。动态路径、分页查询或普通锚点需要合并时，可明确配置归并规则。 |
| 自动发现 | 在当前测试标签页、已就绪的主页面中观察支持的 Fetch 和异步 XHR。请求以发起时的 URL 分组，迟到结果留在原组。已有会话记录立即展示。 |
| 首次覆盖 | 未出现过的请求可通过原页面查询、翻页或用户选择「刷新并采集」补齐。当前接入方式覆盖不了的来源显示原因。导入文档可补充配置入口。 |
| 导入格式 | 首版支持本地单文件 OpenAPI 3.0/3.1、Swagger 2.0 的 JSON 或 YAML。预览接口方法、路径、操作名、格式、模型或示例，并确认实际 API 域名及路径前缀。外部引用显示为待补充。 |
| 导入与发现合并 | 选中的导入接口可以关联到当前页面，触发前即可设置场景。真实请求出现后按方法、API 来源和路径合并，保留「文档导入」及「已实际请求」两种来源。同一端点既有文档又有请求时显示一行。 |
| 共用 POST 地址 | 使用 API 方法、来源和路径识别接口行。在该行内可对指定 JSON 字段配置等值条件。用户可以显式选择整个端点。文档 `operationId` 用于标题与查找。运行时以请求实际字段匹配。 |
| 快速筛选和忽略 | 按业务、静态、地图、有规则或已忽略筛选。勾选后可批量忽略当前可见接口，也可按路径前缀设置站点级规则。完整前缀地址可以限定 API 来源。保存前预览当前影响数量，可撤销。活动规则继续按原设置执行，并可在「有规则」中查看。 |

OpenAPI 说明的是 API 接口和数据结构。前端页面的归属来自真实页面请求或用户关联。导入过程在本机解析，用户启用规则后仍由页面自然发起请求。[OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.1.html) · [Swagger 2.0](https://spec.openapis.org/oas/v2.0.html)

## 4. 异常场景与响应配置

| 场景 | 版本 | 可验证的行为 |
| --- | --- | --- |
| HTTP 错误 | 首版 | 400、401、403、404、429、500、502、503、504 提供预设，可编辑状态码和响应体。429 预设带可配置的 `Retry-After`。 |
| 空数据 | 首版 | 提供 `[]`、`{}`、`null`、HTTP 204，以及保留业务结构的空列表。204 返回无正文。 |
| 业务错误 | 首版 | 支持 HTTP 200 和项目需要的 `code`、`message`、业务数据等字段，观察页面业务失败反馈。 |
| 慢响应和乱序 | 首版 | 合成响应可叠加固定延迟。给不同查询或请求体条件设置不同延迟，可以验证旧结果是否覆盖最新查询。 |
| 网络失败 | 首版 | 模拟请求以网络错误结束。HTTP 504 仍作为可自定义的 HTTP 响应。 |
| 异常正文 | 首版 | 可配置 JSON 和文本，测试字段缺失、类型错误或无效 JSON。只有选择坏正文场景时才允许使用无效 JSON。 |
| 重试、间歇故障与其他传输 | 后续 | 探索连续失败后恢复、流式响应、SSE、WebSocket、Worker 和 iframe 等覆盖。 |

优先使用实际响应的媒体类型和已选样本，由文档、站点模板或手动配置补充。可覆盖状态、媒体类型、正文和业务字段。空列表可保留 `code`、`message` 等业务结构，并预览 `data.list=[]`、`data.total=0` 等变更。缺少基础结构时提供模板和手动输入。

## 5. 规则、批量操作与复测方案

- **单条与批量。** 在行内快捷启用或详细编辑。批量先预览页面组、接口、查询或 JSON 条件和返回结果，范围冲突时定位相关规则。完整校验后整批启用。切换 URL 时保留原组的草稿，回到该组可继续。
- **自定义场景。** 可从场景库新建，或将编辑中的响应保存为命名场景。保存的状态、类型、正文及延迟可跨页面用于单条和批量设置。
- **方案保存。** 保存站点、页面组、接口与匹配条件。正文可保存用户预览确认过的脱敏合成响应，也可保存固定版本的业务模板与字段变更。真实样本仅用于当前会话。模板缺失时提示补齐，用户可以手动修改或重新采样。
- **复测。** 方案可填写前置状态、触发步骤和预期 UI 表现，例如「先查询到订单 → 点击查询 → 列表显示空态」。载入后先确认目标，启用后命中数按本轮规则计算。方案跨重启保留，运行状态由用户显式启用。
- **暂停与恢复。** 区分「等待页面发请求」「请求已放行」「本轮规则已命中」「执行失败」。停止后提示重新触发业务操作，确认是否已观察到真实请求。应用自己的缓存、表单和路由状态由被测应用管理，页面恢复需单独判断。

## 6. 可靠性与支持边界

- 首版覆盖当前测试标签页主页面的 Fetch 和异步 XHR，包括 JSON POST。规则按页面组和端点隔离，页面层生成的合成结果以 APIFaultLab 工作台为准，DevTools Network 用于查看真实网络请求。
- 对已接管的 POST，在调用原生网络发送前生成合成响应或模拟失败。取消、超时和中间错误也应在页面内结束，避免自动回退为真实 POST。只对已确认被接管的请求承诺这项行为。首屏、旧网络函数引用、Worker 或其他执行环境的覆盖分别验证。
- 采集开关和活动规则属于测试标签页，关闭工具栏弹窗或 DevTools 后继续按当前配置运行。跨源导航或关闭标签页结束会话。同标签页、同源刷新保留已启用规则和接口目录，工作台在新文档确认后显示模拟已恢复。首屏请求与恢复的时序单独验证。
- 接口文档和项目配置在本机处理。完整请求体、Cookie、鉴权头、真实响应正文只按必要范围在会话内使用。只有用户确认过的合成响应、模板和显式匹配值进入持久化方案。

## 7. 首版验收

| 验收任务 | 预期结果 |
| --- | --- |
| DevTools 打开并模拟 POST | 同一个标签页先打开 DevTools 再启用模拟。可继续查看 Console 和断点。命中的查询 POST 收到 200 空列表，服务端该次收到 0 次。未匹配 POST 原样发送 1 次。 |
| 共用 URL 与页面归组 | 页内切换时页面 URL 不变，接口组保持不变。`POST /api/query` 中指定 `operationName` 的请求命中，其余操作放行。切换到不同页面 URL 后加载独立组。 |
| 导入接口后配置 | 导入含 POST 的 OpenAPI 或 Swagger 文件，确认映射并关联当前页。在首次触发前可配置。真实请求出现后合并到同一行，保留来源与真实观察状态。 |
| 故障组合与取消 | 批量启用空列表、延迟和 503，分别收到命中状态。停止或取消已接管的延迟 POST 时，服务端该次收到 0 次。 |
| 跨重启复用 | 保存空列表方案，关闭浏览器后重新打开，无需原始响应样本即可预览用户确认的合成响应。模板不可用时显示补配置入口。 |
| 刷新后恢复 | 未保存为方案的运行规则也可在同一标签页刷新后恢复。等待新文档确认再查询，原条件命中。停止规则或换到其他站点后，刷新不恢复旧规则。 |
| 忽略与异常场景 | 忽略 `/assets/` 后业务接口和 `/assets-v2/` 保持可见。切换分类后批量操作仅作用于可见选中项。保存自定义响应场景后另一页面可复用，429 可观察 `Retry-After`。 |
| 页面恢复 | 原页面真实查询有数据，模拟空列表后查询显示空态，停止后重新查询观察到真实请求，最终恢复真实列表。应用未发新请求时显示等待提示。 |
| 不确定的接管 | 当前文档的代理尚未应答时显示未就绪。模拟故障、早期请求无法拦截和停止未确认的状态分别可见。 |

实现选型和浏览器验证范围见 [技术选型与架构设计](技术选型与架构设计.md)。
