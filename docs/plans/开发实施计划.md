# 接口异常测试插件开发实施计划

**目标** 交付可作为解压扩展加载的 Chrome Manifest V3 首版，从实际页面完成接口发现、POST 模拟、批量应用和恢复真实请求，并支持本地接口文档与方案。

**架构** WXT 打包 Vue 3 工具栏弹窗、DevTools 工作台、扩展 Worker，以及授权页面里的 Fetch/XHR 适配器和隔离消息桥。Worker 按标签页和文档提交完整规则快照，页面适配器就地执行。

| 步骤 | 文件与实施 | 验证 |
| --- | --- | --- |
| 扩展入口 | `wxt.config.ts`、`entrypoints/popup/`、`entrypoints/devtools/` | 生产清单包含 Chrome 142、原生弹窗和 DevTools 注册页，工作台绑定确切的被检查标签页。 |
| 规则编译 | `lib/model.ts`、`lib/rules.ts` | Node 测试覆盖同 URL、POST 条件、路径、响应体和批量冲突。 |
| 页面适配 | `entrypoints/page-main.ts`、`entrypoints/page-bridge.ts` | 测试接管后的响应、取消与失败处置，页面脚本仅接收当前文档规则。 |
| 接口导入 | `lib/openapi.ts`、工作台导入区 | 覆盖 Swagger 和 OpenAPI 的本地引用、环境地址确认、导入后合并。 |
| 工作台与恢复 | `entrypoints/workbench/`、`entrypoints/background.ts` | Vue 类型检查、生产构建、方案持久化和刷新后恢复已启用规则。 |

先运行 `npm run typecheck`、`npm test` 与 `npm run build`。Chrome 实测单独征求本次授权，优先验证保持同标签页 DevTools 打开时，命中的 POST 后端计数为 0，其他操作照常送达，停止后重新查询恢复真实数据。
