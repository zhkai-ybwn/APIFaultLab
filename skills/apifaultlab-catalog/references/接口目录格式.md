# APIFaultLab 接口目录格式 v1

最外层是 JSON 对象，包含以下字段。

| 字段 | 格式 |
| --- | --- |
| `format` | 固定为 `apifaultlab-catalog` |
| `schemaVersion` | 整数 `1` |
| `page` | 需要关联的完整 HTTP(S) 网页 URL，与 APIFaultLab 中的当前页面一致 |
| `operations` | 1 到 500 个操作 |

页面匹配包含查询参数和片段。页面 URL 需要携带敏感参数时，先使用脱敏的测试页整理目录。

每个操作的字段如下。

| 字段 | 格式 |
| --- | --- |
| `id` | 文件内唯一且稳定。最多 120 个字符，使用英文字母、数字、点、下划线、冒号或连字符，以字母或数字开头 |
| `title` | 给用户看的操作名称，最多 240 个字符 |
| `method` | `GET`、`HEAD`、`OPTIONS`、`POST`、`PUT`、`PATCH` 或 `DELETE` |
| `origin` | 接口的 HTTP(S) 来源。可含非默认端口，省去路径、末尾斜杠和登录凭据 |
| `path` | 以斜杠开头的路径。可使用 `{id}` 参数，省去查询参数和片段 |
| `source` | `observed` 表示来自实际请求记录，`documented` 表示来自文档，`inferred` 表示从代码推断 |
| `conditions` | 可选的匹配条件数组，最多 20 项。各项同时满足时匹配，省略时不附加条件 |
| `contentType` | 可选的已知响应类型，例如 `application/json` |

条件包含 `source`、`path` 和 `value`。查询参数使用 `"source": "query"`，字段为参数名，值为字符串。JSON 正文使用 `"source": "json"`，字段优先写 JSON Pointer，例如 `/operationName`，值可以是字符串、数字、布尔值或 `null`。同一字段在一组条件中只出现一次。目录会拒绝识别出的认证字段和令牌内容。避免填写密码、令牌、标识个人的条件值或业务敏感参数。

多个操作可以共用方法、来源和路径。导入后它们会汇总到一个接口下。用户可以在接口详情选中一个操作，将条件带入规则草稿。将同一个文件再次导入时，匹配到同一接口和操作标识的记录会更新，其他操作保留。

目录仅记录接口元数据和匹配条件。响应示例、运行规则和访问凭据由用户在各自流程管理。完整示例见[共用请求目录](共用请求目录.json)。
